# ⚒️ APK Forge — مصنع تطبيقات أندرويد بالذكاء الاصطناعي

منصة تصف لها تطبيقك بالعربي، فتبنيه بالذكاء الاصطناعي بإحدى خمس لغات، وتعرض **معاينة فورية** قبل البناء، ثم تبني ملف **APK** جاهزاً عبر GitHub Actions وترسله للزبون بالإيميل.

## الميزات

| الميزة | التفاصيل |
|---|---|
| 5 لغات | HTML/CSS/JS · React (Vite) · Flutter · Kotlin (Jetpack Compose) · Python (Kivy) |
| تطبيق أو تطبيقان مترابطان | مثل زبون + إدارة، متصلان لحظياً عبر قاعدة بيانات مشتركة |
| قواعد البيانات | **Supabase** (إنشاء الجداول + الصلاحيات RLS + Realtime تلقائياً) أو **Firebase Realtime Database** |
| حسابات الزبائن | ربط المشروع بحساب Supabase خاص بكل زبون |
| معاينة فورية | داخل إطار جوال، وتتحدث أثناء الكتابة. HTML وReact تعمل حقيقياً في المتصفح؛ Flutter/Kotlin/Python بنسخة ويب مطابقة |
| 4 مزودات ذكاء اصطناعي | Gemini (حتى 3 مفاتيح بالتناوب) · Claude · OpenRouter · Groq، مع الانتقال التلقائي عند الفشل أو نفاد الحصة |
| مساعد تعديل | "أضف شاشة تسجيل دخول"، "غيّر اللون"… يعدّل الملفات المطلوبة فقط |
| بناء سحابي | دفع إلى مستودع `apk-app` ← GitHub Actions ← الـ APK في Releases |
| تسليم | تنزيل مباشر من اللوحة، أو إرسال للزبون عبر Gmail أو Brevo مع الـ APK مرفقاً |

## التشغيل

```bash
npm install
cp .env.example .env     # اختياري: يمكنك إدخال المفاتيح من الواجهة بدلاً من ذلك
npm start                # http://127.0.0.1:3000
```

يتطلب Node.js 20 أو أحدث. البناء نفسه يتم على GitHub، فلا حاجة لتثبيت Android SDK أو Flutter عندك.

## خطوات الاستخدام

1. **الإعدادات**: أضف مفتاح ذكاء اصطناعي واحداً على الأقل، ومفتاح GitHub (بصلاحيات `repo` + `workflow`)، ومفاتيح Supabase/Firebase إن أردت. اضغط "اختبار الاتصال" لكل قسم.
2. **مشروع جديد**: اكتب الوصف، واختر اللغة وعدد التطبيقات وقاعدة البيانات.
3. **المعاينة والتعديل**: عدّل الكود يدوياً (يُحفظ تلقائياً والمعاينة تتحدث فوراً)، أو اطلب التعديل من المساعد.
4. **📦 ابنِ APK**: تتابع الحالة من اللوحة، ويظهر زر التنزيل عند الانتهاء.
5. **إرسال للزبون**: اكتب إيميله، فيصله الـ APK مرفقاً (حتى 20MB لكل ملف، والأكبر يُرسل كرابط).

## كيف يعمل

```
الوصف ─► خطة (التطبيقات + SQL/قواعد + عقد البيانات) ─► تطبيق SQL على Supabase
      ─► توليد ملفات كل تطبيق ─► معاينة فورية ─► تعديلات
      ─► دفع إلى GitHub (projects/<مشروع>/<تطبيق>) ─► Actions ─► Release (APK)
```

- كل مشروع يوضع في مجلد داخل نفس المستودع، ولكل تطبيق سير عمل مستقل (`.github/workflows/build-<مشروع>-<تطبيق>.yml`).
- **ملفات يولّدها النظام** (للقراءة فقط، والذكاء الاصطناعي لا يستطيع تعديلها): ملف الربط (`config.js` / `config.dart` / `Config.kt` / `config.py`)، وملفات Gradle وManifest، و`buildozer.spec`، و`package.json`. هذا يضمن نجاح البناء ويمنع تسريب المفاتيح.

| اللغة | أداة البناء | مخرج البناء | الوقت التقريبي |
|---|---|---|---|
| HTML | Capacitor 6 + Gradle | debug APK | 3-6 دقائق |
| React | Vite + Capacitor 6 | debug APK | 3-6 دقائق |
| Flutter | `flutter build apk --release` (موقّع بمفتاح debug) | release APK | 6-10 دقائق |
| Kotlin | Gradle 8.9 + AGP 8.5 + Compose | debug APK | 4-8 دقائق |
| Python | Buildozer + python-for-android | debug APK | 15-30 دقيقة (أول مرة) |

## الأمان

- المفاتيح تُحفظ في `data/settings.json` على جهازك فقط (المجلد مستثنى من git)، وتظهر في الواجهة مقنّعة (`••••abcd`).
- التطبيقات المولّدة تحصل فقط على القيم العامة: رابط Supabase مع مفتاح `anon`، أو رابط Firebase. مفتاح الوصول `sbp_` لا يغادر الخادم. لذلك تعتمد حماية البيانات على سياسات RLS التي يولدها النظام، فراجعها في تبويب "قاعدة البيانات".
- الخادم يعمل افتراضياً على `127.0.0.1`. للتشغيل على سيرفر عام يجب ضبط `ADMIN_PASSWORD` (يرفض الخادم البدء بدونها).
- مسارات الملفات التي يرجعها الذكاء الاصطناعي تُفحص لمنع الكتابة خارج مجلد التطبيق.

## الاختبارات

```bash
npm test
```

تغطي الاختبارات: تحليل ردود الذكاء الاصطناعي، والتبديل بين المزودات، وتقنيع المفاتيح، وملفات كل لغة وسير عملها، والمعاينة، وسيناريو كاملاً (خطة ← تطبيقان ← تعديل ← دفع إلى GitHub وهمي) بدون إنترنت.

## هيكل المشروع

```
server/
  index.js            الخادم وواجهة API
  settings.js         الإعدادات والمفاتيح
  generator.js        التخطيط والتوليد والتعديل وربط قاعدة البيانات
  builder.js          الدفع إلى GitHub، متابعة البناء، الإرسال
  stacks.js           تعريف اللغات: الهيكل، ملف الربط، سير العمل
  store.js            تخزين المشاريع والمهام
  ai/                 المزودات، الموجّه، التعليمات، التحليل
  integrations/       GitHub · Supabase · Firebase · Mail
shared/preview.js     محرك المعاينة (يعمل في المتصفح)
web/                  الواجهة (عربية RTL، بدون خطوة بناء)
test/                 الاختبارات
```
